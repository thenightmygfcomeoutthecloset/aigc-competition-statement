# Image Generation — 逆向图像过程材料生成规范

> 本文档定义在 **Reconstruction Mode（逆向重构模式）** 下，Agent 如何通过能力导向（Capability-Based）的图像生成/编辑工具，实际生成真实的过程图片文件，并建立演进因果链。

---

## 一、能力导向原则（Capability-Based Design）

Skill **绝不硬编码** 任何特定的模型名称（例如不要绑定 `gpt-image-3` 或任何商业供应商专用名）。

**调用判定逻辑**：
```text
IF 宿主 Agent 环境拥有图像生成/图像编辑工具 (如 generate_image 或相应 MCP 工具):
    实际调用该工具生成过程图片文件
    将生成的图片保存到项目输出目录，并在文档中真实引用
ELSE:
    执行 Fallback 降级逻辑（绝不虚构假图片文件名）
```

---

## 二、逆向图像任务类型与生成要求

逆向生成的目标不是“再画一张最终成品”，而是“反向剥离细节，生成可信的前期与中期材料”。生成时必须向图像生成工具输入明确的语义约束：

### 1. `reference_to_sketch`（构图草图）
- **输入参考**：最终作品图
- **语义约束**：
  - 保留核心主体的大体轮廓、位置与动态；
  - 保留画面的主要三分法/向心/对角线构图；
  - 保留空间透视视平线与景深比例；
  - **彻底去除** 最终的高清材质、复杂光影、高光反射和精细纹理；
  - 呈现为粗糙铅笔线条、概念草稿纸笔触、结构辅助线形式；
  - **严禁** 仅仅在最终成品图上添加廉价的“素描滤镜”。

### 2. `reference_to_color_block`（色彩氛围大关系稿）
- **输入参考**：最终作品图
- **语义约束**：
  - 保留画面主色调、辅助色与环境色温冷暖关系；
  - 极致简化几何形体，去除所有细节肌理与锐利边缘；
  - 呈现为大笔刷平涂、模糊色块、色彩氛围概念图状态；
  - 用于佐证创作初期对全局色彩与光影氛围的探索。

### 3. `reference_to_lineart`（线稿约束图）
- **输入参考**：最终作品图
- **语义约束**：
  - 提取画面主要角色/物体的黑白清晰轮廓线；
  - 简化或虚化复杂的背景琐碎元素；
  - 呈现为可用于 ControlNet Lineart / 传统手绘线稿底稿的形式。

### 4. `reference_to_composition_draft`（几何透视骨架稿）
- **输入参考**：最终作品图
- **语义约束**：
  - 仅用几何体块（立方体、球体、透视引导线）标示主体占位；
  - 适用于宏大建筑、城市天际线、复杂机械或空间纵深场景。

### 5. `reference_to_intermediate_generation`（阶段性 AI 中间结果）
- **输入参考**：前序草稿 + 阶段性 Prompt
- **语义约束**：
  - 必须与最终作品存在强烈的关联性和相似度；
  - **但完成度必须明显低于最终成图**；
  - **必须包含合理、可观察的阶段性视觉瑕疵**（例如：光影方向不明确、背景细节单薄、特定材质偏生硬、局部边缘轻微模糊）；
  - 这些视觉瑕疵将作为下一阶段调整 Prompt 和参数的**真实因果依据**！

## 三、过程视觉链设计（Minimal but Sufficient）

Reconstruction Mode 应根据作品的复杂度和推导出的管线，组织最精简且足以形成证据闭环的视觉链（通常为 3～4 步），**严禁为了凑数机械堆砌无关图片**：

### 方案 A：草图约束型管线（推荐）
```text
01_reconstructed_sketch.png            (逆向构图草稿，标明 [Reconstructed])
       │
       ▼
02_reconstructed_generation_v1.png     (首轮AI初稿：主体成立，但光影偏平、背景空洞)
       │
       ▼
03_reconstructed_generation_v2.png     (调整Prompt后二轮稿：光影确立，局部细节需微调)
       │
       ▼
04_final_artwork.png                   (创作者最终提交的成品，标明 [Verified])
```

### 方案 B：色彩探索型管线
```text
01_reconstructed_color_block.png       (逆向色彩氛围大关系稿)
       │
       ▼
02_reconstructed_generation_v1.png     (基础文生图初版探索)
       │
       ▼
03_final_artwork.png                   (最终成品)
```

## 四、图像生成 Fallback 降级机制

若当前宿主 Agent 环境**没有图像生成/图像编辑能力**（例如在纯文本环境或无生图工具的 CLI 模式中）：

1. **绝对禁止伪造行为**：
   - 严禁假装图片已生成；
   - 严禁凭空写一个并不存在的虚假本地文件路径（如 `![图1](./images/sketch.png)`）；
   - 严禁从网络下载无关图片冒充。
2. **正确执行步骤**：
   - 继续完成作品的深度结构化分析（Stage 3）与管线推导（Stage 4）；
   - 生成完整的逆向 Prompt 演进链（V1/V2/V3）与参数建议；
   - 给出用于生成对应过程图的 **精细生图指令（Generation Prompts & Specs）**，指导创作者在外部工具中手动生成；
   - 在生成的 Word 文档草稿中，图片位置明确标注占位说明：
     `【待插入复现过程图：请使用下方 Prompt 在 AI 工具中生成构图草稿】`
3. **合规审查状态联动**：
   - 在 Stage 7 Submission Check 中，明确将状态标记为：
     `⚠️ Required Visual Evidence Missing (宿主缺少生图工具，过程图片未实际渲染，需创作者手动补齐)`；
   - **绝对不得标记为“全部合规通过（Fully Compliant）”**。

---

## 五、反伪造铁律（Anti-Hallucination for Images）

1. **所有自动生成的逆向图片，证据等级一律为 `[Reconstructed]`**，绝不能因“图片已经被实际画出来了”而升级为 `[Verified]`。
2. **严禁生成虚假的软件操作历史截图**：
   - 可以生成：草图、线稿、色块图、中间阶段生成图、概念探索图。
   - **坚决不得生成或伪造**：Photoshop 工程图层面板截图、ComfyUI 节点连接截图、Midjourney Discord 频道历史截屏、即梦/SD WebUI 历史记录页、EXIF 元数据截图。
   - 即使生图模型具备绘制软件 UI 的能力，也绝不得将生成的模拟 UI 图片放入文档充当真实操作证据！
